# All currently verified tasks with ground-truth depth
Verified scope: **43 individual task/protocol entries: 24 existing-depth reads, 10 saved-state re-renders, five new collections and four native RGB-D interaction protocols**. The redundant PhysMani overview is excluded; normal/high-speed entries are counted separately. These are not 43 independent physical families. CLEVRER videos and unaccepted TurnFaucet-v1 are excluded.

On 2026-10-11, existing artifacts were checked read-only: all 39 NPZs / 468 frames passed numeric SHA256, dtype, RGB-depth alignment, valid-pixel, calibration and GIF-decoding checks. One 111-frame HDF5 per P0 protocol also passed RGB-D/time/persistent-point transport audits. No new simulation, collection or inference was launched. See [depth_recheck.json](depth_recheck.json) and [structured sources](depth_capable.json).

## Interpreting the categories
Categories describe **how accepted depth samples were obtained**, not every potential simulator capability. All 39 old samples can now be read, but ten were rendered from states and five came from new trajectories. This does not imply the original RGB release contained depth, nor permit pairing new depth with old video. None of these 43 entries requires monocular depth estimation.

## Outside verified ground-truth-depth scope
- **CLEVRER**: standard videos lack project-verified pixel-depth GT. Object-centre 3D labels are not surface depth. Video-derived depth remains estimated.
- **TurnFaucet-v1**: matching assets/data are unaccepted; a legacy v0 GIF does not establish v1 availability. This is an asset-verification issue, not evidence it can only ever use estimated depth.
- **Old conveyor/puck RGB**: accepted new collection does not establish exact depth recovery for every old trajectory.
- **CoPhy BallsCF/CollisionCF and other Physion categories**: accepted examples cover Blocktower/Collide only, not every subset.

## Implications for 4D MAE / World Models
GT depth gives per-frame observed point clouds, not automatically persistent physical point identities, contacts, aligned controls or articulated-link assignments. All 43 entries have verified depth paths. The four P0 protocols have the most complete evidence for the current unified oracle-point/contact schema; other tasks still require conversion and acceptance.

Preserve metres, ray/Z type, valid masks, synchronized RGB/calibration and actual times/frame IDs. Each of the 39 NPZs contains only twelve uniformly selected frames. GIF playback cadence is illustrative and not a dense action-conditioned training clock. Full trajectories, views, segmentation, persistent points, contacts and leakage-free splits need separate preparation.

Local old samples: `dev/benchmarks/benchmark_depth_samples/<sample_id>/sample.npz` with metadata/preview GIFs. New protocols: `dev/benchmarks/benchmark_interaction_data/acceptance-006/*.h5`. Numeric arrays are neither in Git nor publicly published; code/document synchronization does not automatically copy raw data. No PR; this update uses `task/benchmark-subset-v1`.
