# Matched RGB-H / FlowACT training support

**Implemented: official action preparation, synchronized replay, immutable garment splits, matched training, prior-zero validation, complete continuation, offline evaluation, and native simulator rollouts. Formal 30k-step/multi-seed experiments are not complete.** See `training-validation.json` for executed receipts and [Chinese commands](training.zh-CN.md).

All four controls use 16 three-camera 640×480 RGB observations, spaced by three 90 Hz physical ticks (0.5 s), the same ImageNet normalization/ResNet18/4×4 spatial tokens, measured current 12D joints and 100×12 action chunks. Dataset windows/order, paired initialization, training-only statistics and optimizer budget match. RGB-H uses no GT fields in its dataset, encoder or online history API. Geometry, Tracks and Tracks+Completion add current cloth geometry, past tracks and the auxiliary objective respectively. Equal steps do not imply equal compute. GT remains a privileged upper bound; there is no RGB tracker.

`prepare_flow_sources.py` pins `lehome/dataset_challenge@2bfdd30795ae25bba189649bf71cbb33f5b2a03c`. It prepares all ten Seen long sleeves: 250 episodes/83068 frames, by fetching approximately 7.20 MB of Parquet column chunks and metadata rather than original RGB/depth. Receipts cover pinned revision, fetched-range hashes and derived-file hashes, **not full upstream Parquet verification**. First-episode actions/pose match the existing merged source and synchronized replay.

`collect_flow_dataset.py` serially replays official controls on one selected GPU, preserving failed attempts and resuming completed cases. It records new lossless RGB and persistent cloth GT at every physics step, never combines original RGB with another replay. `flow_dataset.py freeze` fixes episode membership, full file SHA-256, shared windows and normalization fitted only on training garments. Seen_0–7 train, Seen_8 validation, Seen_9 test. Formal inventories require 200 full training and 25 validation episodes; completed replays retain outcome labels without silently filtering failures.

The development inventory contains only three genuine episodes: Seen_0/1 train (669 actions/223 windows), Seen_8 validation (357 actions/119 windows), no test episodes. Prepared action sources are not equivalent to a complete synchronized GT dataset. Remaining full replays and formal training are pending.

Use `train.sh` for isolated Python/cache/CUDA/thread settings. `configs/flow-formal.json` defaults to 30000 optimizer steps, effective batch 16 (microbatch 1, accumulation 16), policy/backbone lr 1e-5, AdamW, clipping 1, 500 warmup steps then cosine to 0.1×lr; validation every 500 steps on 128 fixed uniformly selected windows, checkpoint every 1000. `run_flow_suite.py` runs all four controls and seeds 1000/1001/1002 serially on one GPU. `flow-dev.json` is a six-step engineering recipe; `--pilot --tiny` uses small Transformers but the same native-resolution RGB/history. Fixed point subsets are default; explicit epoch resampling affects training only, validation stays fixed.

`last.pt` atomically stores model, optimizer, scheduler, all RNGs and the consumed-example cursor. Prefetched examples do not advance committed training progress. SIGINT/SIGTERM stop at optimizer boundaries. `--resume` restores the original run with unchanged dataset/recipe/core code, retaining uncommitted log tails. `checkpoint.pt` is the latest inference model; `best.pt` uses **validation prior-action L1 only**, never the test split. Exact continuation is checked in the same software/hardware environment, not guaranteed bitwise across devices. Adaptive pooling uses identical explicit average bins to avoid CUDA's nondeterministic backward; value/gradient parity is unit-tested.

`evaluate_flow.py` verifies checkpoint/dataset identity and training statistics, reports valid-element-weighted normalized action L1/radian MAE, and all/moving-point completion EPE with static references. Native `run.sh flow-rollout` supports all conditions with matched cameras/physics/initialization. RGB-H GT-policy reads must be zero; success GT is an external metric. Standard evaluation uses a 600-step cap and 50 post-success steps. Short/pilot checks require `--pilot` and are not performance estimates.

`verify_training_package.py` executes real garment-disjoint short training, prefetched two-worker interruption/resume at step 3→6 against continuous step 6, complete state equality, changed-recipe rejection, full-architecture optimizer updates and reproduction of best-checkpoint offline validation. These are training infrastructure checks, not evidence that flow improves folding. [Anonymous training report](https://peiqil.com/dynamic-robot-bench-viewer/lehome/training/).

Executed native checks: RGB-H and Tracks+Completion each ran three steps with their trained checkpoints and auxiliary heads removed. Both 960×480 videos fully decoded four frames; policy GT-track reads were zero for RGB-H and four for Flow. These are interface checks only. All 23 Baidu LeHome tests passed; the Mac CPU suite ran 72 tests with 57 passing and 15 dependency skips.
