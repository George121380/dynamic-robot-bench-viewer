Query & completion

A point query is its current 3D coordinate (anchor): where was this point, and where will it go? HPT's learned queries are separate model parameters.

Point selection, decoder inputs and training details

Point selection. This frozen setting samples 64 persistent object-local points per object with seed 42, weighted by exterior surface area. The first 32 belong to C and the other 32 to Q: 64 C + 64 Q across the cube and tool. Simulator poses provide their world coordinates, including camera-hidden surfaces. Q withholds different points on the same objects; it is not a held-out-object experiment.

What reaches the model. HPT receives current RGB, robot state and C history, including the current frame. Q anchors enter the trajectory decoder, not HPT. For each point, Tθ sums projections of the anchor, all 30 displacement slots and their observed/noisy flags into one point token. The decoder adds flow time τ, mixes points and cross-attends to the 16 HPT context tokens. Its output is a velocity for every displacement coordinate.

Sampling. Initialize the unknown displacement slots with Gaussian noise and integrate from τ = 1 to 0 in 50 Euler steps. Clamp valid C history after every step; all 30 Q slots are unknown. Outputs represent p(t + k) − p(t) for k = −15,…,−1,+1,…,+15 at 0.05 s intervals. Add the current anchor to the denormalized displacement to recover a world position. The current displacement is zero, so it needs no output slot.

Training. For a normalized target y and Gaussian noise ε, use xτ = (1 − τ)y + τε in unknown slots and train the velocity toward ε − y. Known C history stays clean. Target trajectories enter through this noised training state, not as HPT context or clean Q history. Average the three auxiliary masked MSE terms (C future, Q past, Q future); invalid labels do not contribute. The action loss is trained alongside this auxiliary objective. C and Q use separate calls to the same decoder and tokenizer weights.

Inside HPT

HPT mixes observation features with learned action and future tokens, producing conditions for the two flow-matching heads.

  • Learned queries: parameters inherited from EgoWAM, distinct from sampled noise and point-query anchors.
  • Generation: HPT runs once per observation; each head uses its fixed context for 50 steps.
  • Two inputs: Tθ encodes noisy tracks; the 16 future-context tokens enter the decoder separately.
Sources and implementation notes

B5 adds point-history input, C/Q completion and shared trajectory-tokenizer weights. The trunk and 64 action / 16 future tokens are inherited from EgoWAM. This run initializes the trunk from scratch and the RGB backbone from ImageNet.

Only action/future output positions are read out. Action inference retains future tokens in the trunk and omits the trajectory decoder. Observed C history stays fixed during trajectory generation.

C denotes points with observed history; Q denotes additional points with current anchors only. PullCube supplies privileged simulator history. The input history includes the current frame; its displacement is zero and is omitted from the 30 output slots.

The action and trajectory heads are flow-matching models. Training losses supervise velocity fields, while sampling integrates them for 50 Euler steps. The trajectory decoder is called separately for C and Q; action inference does not call it. Learned future queries remain in the HPT during action inference.
