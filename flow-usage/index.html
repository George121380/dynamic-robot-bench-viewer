1 · 研究问题与当前判断

当前负结果尚不能否定 flow；更具体的事实是，现有策略没有明显使用过去点运动，过去补全也未稳定帮助动作。本次核查八篇论文的方法、实验、消融和局限。它们将 flow 用作未来计划、共享表征监督或动作条件动力学；这些目标与历史输入／过去补全不同。

范围：机器人操作中的 2D tracks、3D scene flow 和跨时间点轨迹。FlowPolicy 的 flow matching 是生成分布的速度场，不等于场景物理运动；G3Flow 的 semantic flow 也不能直接当作动态轨迹证据。检索日 2026-10-19，版本固定在各条原文链接；这不是穷尽性综述。

2 · 前人如何使用 flow

早期视觉策略同时学习任务、状态与控制；视频轨迹提供了可复用的中间接口。相关工作并没有给出“任何 flow 辅助项都有收益”的结论。最关键的分类维度是：预测过去还是未来、有没有候选动作条件、下游在哪里读取、监督是否更新决策主干。下面按接口比较，不能横向比较不同论文的成功率。

3 · 从已有知识重建思路

以下是我们的重建：静态图像压缩了运动信息，视频重建又花费大量容量复原外观。点轨迹可以描述任务进展，同时保留局部几何。于是产生两条合理路线：用轨迹表示“下一步应该发生什么”，让控制器跟随；或监督共享表征预测未来，让它保留对行为有用的变化。进一步需要比较候选动作时，预测器必须回答“如果执行这个动作，会发生什么”。三者对应不同问题。

4 · 核心 intuition

flow 的潜在价值来自它承载的可执行进展、被遗漏的状态或动作后果。仅增加轨迹 token 不会保证模型读取它。好的论文把这个接口和监督／控制路径连起来，并在相应任务上验证。对我们而言，“怎样让历史 flow 有用”与“怎样预测未来计划”应分别检验。

5 · 逐篇 pipeline 与证据

下列方法细节来自原文；借鉴建议是我们的判断。点击展开。

ATM2024 · 任意点的未来 2D 轨迹

方法：视频经 tracker 生成伪标签 → 预训练未来轨迹预测器 → 预测轨迹同时在 policy Transformer 输入端和动作 MLP 前融合。轨迹充当细粒度 subgoal；policy 仍读取图像。

原文证据：最有针对性的消融：LIBERO-Goal 上，仅 early fusion 为 5.33%，仅 late fusion 为 72.83%，两者为 77.83%。这是同文架构消融，不是跨论文排名。

边界：学习到的未来计划与已观察历史不同；额外视频预训练也是条件。单个任务套件的融合结果不能直接外推成 ACT 的保证。

我们的借鉴判断：优先借鉴动作头附近的显式计划接口。

ATM · IV-A/B; V-C, Table III; VI
Im2Flow2Act2024 · 物体未来 2D 轨迹＋visibility；初始 3D 锚点

方法：人类视频训练整段物体 flow 生成器；4,800 条仿真 play 训练 flow→action。执行时在线跟踪当前点，temporal alignment 估计剩余计划，再交 diffusion action head。

原文证据：flow 明确描述物体应如何移动，减少 human/robot 外观依赖；低层策略依靠 play 中动作与物体响应的配对学习。

边界：不是纯 3D scene-flow 模型。附录中布料仿真生成 flow 难以精确引导抓取隐藏的细小辅助块；轨迹合理仍可能抓不住。

我们的借鉴判断：借鉴进度对齐和接触附近的可执行性检查。

Im2Flow2Act · 3.1–3.2; 4.3; Appendix A/B/D/E
3D Flow Diffusion Policy2025 · scene-level query points 的未来 3D 位移

方法：RGB-D→PointNet 全局／局部特征→flow diffusion 预测未来 16 步→1D temporal conv＋pooling→与 observation 特征拼接→action diffusion。仿真用 mesh 轨迹；真机用 CoTracker＋逐帧 depth。

原文证据：真机八任务平均成功率 27.5%→56.9%；每任务 50 demos、20 次评测。scene 采样相对仅 object 采样更好，例如 Hammer 48.3%→68.3%。

边界：仿真只训练一个 seed，三个 evaluation seeds 不能充当三个训练重复。主结果支持该系统，未独立证明 flow 比等容量额外网络更优。

我们的借鉴判断：最接近可借鉴的未来 scene-flow→action 接口。

3D Flow Diffusion Policy · IV-B–E; V-A/B, Tables I–III
RoboFlow4D2026 · 主要是夹爪未来 3D 轨迹

方法：RGB 历史＋语言→DINOv2/SigLIP 特征、VGGT 几何蒸馏→FlowDiT。冻结 planner；flow 经 MLP＋attention pooling 后拼到 DP/DiT 条件。按夹爪开闭切 atomic task，慢规划配快执行。

原文证据：LIBERO 的 DP 平均成功率 78.9%→85.1%。主数据管线跟踪夹爪；不可见夹爪的数据才 fallback 到 scene flow。

边界：夹爪路径规划成功不直接证明学会物体碰撞传播。时间重采样是任务进度，也不能直接当作物理速度。

我们的借鉴判断：可借鉴冻结 planner 和动作条件接口；慎用来支持动态 WM claim。

RoboFlow4D · 3.2–3.5; 4.2–4.4; Appendix C/D
3PoinTr2026 · 去掉人／机器人后的 dense 未来 3D 轨迹

方法：人类 stereo 视频的 2D tracks＋depth→3D 伪标签；可见位置 L1 训练两层 Transformer。冻结预测器，逐点轨迹 embedding→Perceiver IO→Diffusion Policy；策略只读预测轨迹。

原文证据：20 条 robot demos 下，Fold Sock 为 9/10，DP3 为 2/10；每项真机结果仅 10 次。flow 是主要任务接口，不会被另一路图像轻易绕开。

边界：固定相机、单任务实验；整段开环执行，作者明确指出不能应对意外动态或在线恢复。

我们的借鉴判断：一个 learned query 可压缩大量轨迹；不必按点数直接堆入视觉 token。

3PoinTr · III; IV-B/E, Table III; VI
EgoWAM2026 · 相机补偿后的未来 dense 3D flow

方法：action tokens 与 future tokens 经过共享 trunk；flow head 用 trunk 特征预测未来运动，梯度塑造主干。推理删除 world head。Track4World＋Aria VIO 生成相机稳定目标，过滤低运动噪声。

原文证据：每任务 300–360 robot demos，加约 10:1 人类数据。附录比较 human action-only、flow-only 和两者联合；联合最好。

边界：研究重点是 human→robot transfer；不能据此期待在 16 条单衣服数据上，补全过去轨迹就获得同样收益。DINO 对某些 OOD 更强。

我们的借鉴判断：借鉴未来目标和共享主干梯度路径。

EgoWAM · 3.2; 4.1–4.3; 5; Appendix A.2/B.2
PointWorld2026 · 输入候选机器人 flow，输出场景响应 flow

方法：当前 RGB-D scene points＋FK 构造的未来夹爪表面点→point backbone→10 步 scene displacement。运动加权、Huber、uncertainty 和 visibility mask 训练；MPPI 用预测点目标代价选择动作。

原文证据：flow 同时约束动作几何与结果评分。论文指出单纯运动加权会放大噪声，需要 robust loss／uncertainty 配合。

边界：附录明确：没有历史或速度输入，默认初始场景静止；也假设机器人能实现给定路径。这限制已在运动的球／布料。

我们的借鉴判断：动态任务要验证 action→flow 响应，而不只优化全点 EPE。

PointWorld · 3.1–3.2; 5.1–5.2; Appendix A.1/A.4
FlowDreamer2025 / RA-L 2026 · 动作条件下的下一步 dense 3D flow

方法：当前 RGB-D＋action→U-Net 预测 flow→降采样 flow/depth 与 RGB latent 通道拼接→diffusion 生成下一帧；联合 flow MSE 与生成损失。MPC 在预测图像上评分。

原文证据：反转 flow、保持 action 不变，生成质量下降，说明下游使用了 flow；这仍不是独立的控制机制因果证明。

边界：作者承认单帧不含初速度，推动后自由运动物体预测困难；真实伪 flow 噪声缩小收益。没有显式几何 warp，不应误写成 warp renderer。

我们的借鉴判断：有可验证的下游消费路径，仍需匹配任务的信息。

6 · 用公式分清四种接口

这里是综述抽象，未声称各论文使用相同网络或损失。令 o 为当前观察，h 为已观察历史，F 为点轨迹，a 为动作，g 为任务。

历史状态：a = π(o, hflow)
未来计划：F̂future = G(o, h, g)；a = π(o, F̂future)
表征监督：z = E(o, h)；L = Laction(π(z), a) + λLfuture-flow(D(z), Ffuture)
动作条件动力学：F̂future = D(o, h, acandidate)；a* = argmin J(F̂future, a)

最后一项能比较不同动作的后果；仅从示范预测“接下来通常怎么动”并不自动得到这种能力。重采样任务进度的轨迹也不能直接换算成真实时间速度。

7 · 论文证据与我们实验的对照

已观测事实：LeHome 当前短训采用同一衣服 16 train／4 validation episodes、四训练 seeds；2000 步 ACT 动作 MSE 0.065236 rad²，Tracks 0.069617。Tracks−Geometry 为 +0.000087 rad²；1500 步过去点运动置零仅增加 0.0446%。这些点来自仿真 GT，因此 tracker 噪声不能解释这轮对照的主要负结果。输入扰动仍有分布偏移，不能当作重训因果消融。

强补全的运动点 EPE 为 30.525 mm，3NN 为 27.578 mm；1500 步 connected−detached 动作 MSE 为 +0.002625 rad²，3/4 seeds 更差。梯度做强未自动改善 actor。补全梯度只覆盖共享 CNN／图像投影／点 MLP，未直接监督主 ACT Transformer；与 EgoWAM 的共享 trunk 路径不同。以上来自既有实验分析，没有重新训练。

文献核查边界：3D FDP 的去噪叙述与式 (3)/(4) 的目标记法不完全一致，复现前应核代码。RoboFlow4D 说 γ>1 的 u=x^γ 会在终点加密；该公式实际在起点更密，不能原样照抄这段说明。两项不影响本页对接口位置的分类。

8 · Take-aways：五句／三句／一句

五句：flow 可以表示状态、计划或动作后果。成功方法为它提供明确消费路径。未来监督与过去补全的任务相关性不同。视频预训练、运动筛选与有效梯度也是收益条件。控制收益最终要在可解释的闭环评估上验证。

三句：先区分历史状态与未来计划。再验证模型是否使用对应信息。最后用匹配的任务和对照判断收益来自哪里。

一句：优先查清 flow 在决策中解决了什么问题。

9 · 最脆弱的假设

迁移到当前项目最脆弱的前提是：flow 中被额外学习的信息，对当前动作仍有条件增量价值。如果当前多视角 RGB＋关节已足够，过去补全可能只是空间插值；如果任务需要历史但模型忽略它，平均补全 EPE 仍可能很好。token 数量差异不是注意力占比或因果证据。现有三轮 oracle-history 也已显示“历史有时有用”与“补全辅助稳定改善未来”不能互相替代。

目前仍未确定：是任务需求弱、过去目标不贴控制、融合／优化问题，还是数据与预算不足。已有证据不允许选一个作为定论。

10 · 一周最小判别实验（提议，未启动）

优先检验“未来预测目标是否比过去补全更贴控制”。保留原 ACT 决策主干和动作头，在共享主干旁接相同尺寸 query decoder。四组：无辅助、过去位移补全、未来位移预测、未来预测但共享主干 stop-gradient。四组保留相同 observation/query 输入、mask、参数布局、初始化和批次；只改变目标时间方向或辅助梯度连接。梯度尺度仅在训练集标定，运动／静止标签配额固定；至少三个训练 seeds。先验证单 batch 与简单基线，再固定预算，禁止根据验证趋势延长某一组。

数据按 episode／初态家族划分，保留独立测试；用训练集预定运动和接触阶段阈值。主指标仍是完整动作块，补报逐 offset、运动／接触子集、future-flow EPE 与静止／恒速／3NN 参考。3NN 是过去补全参考；未来任务要明确另建对应的可部署外推基线。若 future-connected 稳定胜 past 和 future-detached，才支持未来监督路径；若 flow 更准而动作没改善，就否定“预测变准会自然帮助 actor”这一解释。闭环仅在初始化／专家正对照验收后做平衡评估。

第二项再研究 ATM 式动作头附近的独立计划条件，先冻结并验证 planner，再用训练时和推理时一致的预测计划。若额外做 GT future 计划输入，只作为特权信息上界；它含未来答案，不能进入正式可部署成绩。不要在同一轮同时换目标、融合位置、decoder、采样和执行频率。

11 · 最强反例

针对“flow 帮助动态状态推断”的强检验是：构造当前可见几何／任务／候选动作相同、历史速度方向相反的成对场景，评估未来接触时刻和接触后响应。若优势只在新增大容量或更大数据时出现，真实历史与匹配的错误历史无差异，就应优先接受正则化／容量解释。对错配历史同时做训练和评测对照，避免只靠分布外删输入。隐藏摩擦、刚度等不一定能从历史 flow 唯一恢复，要报告不可辨识边界。

12 · 可发展的研究问题

我们的提议，尚未实现，未证明新颖：让历史 flow 服务于“不同可执行动作会怎样改变接触后结果”的响应表示。候选动作通过已知 FK 转为表面轨迹，历史仅通过当前可用输入进入状态；监督未来动态点和接触响应，同时评估动作排序与闭环收益。相邻工具是 system identification、controlled experiments 与 decision-focused model learning。

种子实验沿用上一节成对速度场景，先查三件事：历史能否预测响应差异、能否改变候选动作排序、排序变化能否改善控制。PointWorld 已有 action-conditioned flow，既有项目也已有 paired-response 诊断；所以“加入历史／预测响应”本身不能作为 novelty。潜在增量需在可部署历史、未见接触组合和决策检验上另行检索与证明。
